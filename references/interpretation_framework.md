# 宏观状态解释框架

> 本文件只定义「怎么解释」，不定义「怎么算」。数值一律来自上游代码。

---

## 一、解释的四个层次

```text
① 事实层    指标名称 / 最新值 / 观测期 / 发布日 / 频率     ← 直接来自 observation
② 变化层    d1 / d5 / d20 / WoW / MoM / YoY / zscore      ← 上游算好，只引用
③ 信号层    强/弱、松/紧、扩/缩、分位位置                    ← signal_rules 阈值判定
④ 解释层    为什么会这样、跨资产是否验证、矛盾在哪            ← LLM 只负责这一层
```

**常见错误**：让模型直接看原始数值序列做判断。这会导致同一份数据每次解释不同。
**正确做法**：模型看到的输入是已判定的 signal，不是裸数值。

---

## 二、单指标解释模板

```text
【指标】DR007
【事实】2026-09-10 = 1.4113%，日频
【变化】d1 +0.02 / d5 -0.05 / d20 +0.11；zscore_1y = -0.42
【信号】中性偏松（未触发阈值）
【解读】资金面平稳，无明显收紧压力。
```

禁止出现：`「约」「大概是」「可能接近」+ 数值` 这类模糊表述。数值必须精确到上游给的精度。

---

## 三、六维读法

每维给出 `0~100` 分数，`50` 为历史中性。

| 分数区间 | 语义 |
|---|---|
| 0–30 | 显著走弱 |
| 30–45 | 偏弱 |
| 45–55 | 中性 |
| 55–70 | 偏强 |
| 70–100 | 显著走强 |

**逐维读数不等于结论。** 价值在维度之间的**结构**：

```text
增长 ↑  消费 →  地产 ↓  通胀 ↑  流动性 ↑  外需 →
```

读法：流动性宽松 + 增长改善，但地产仍是拖累 → 「政策宽松已见效于增长，地产链条尚未修复」。
注意：这里说的是**读数之间的相对关系**，不是分数绝对值。

## 四、背离才是信号（Spec §39）

**正常状态没有信息量，背离才有。** 优先输出三类：

### 4.1 宏观 vs 市场
基本面组改善但市场组不确认（或反向）。

> 关键追问：市场在定价什么基本面没反映的东西？还是基本面数据本身有问题？

### 4.2 地产销售 vs 地产信用
销售回暖但信用利差走阔 → 说明市场不信这轮回暖的持续性。

### 4.3 外需 vs 内需
两者方向相反时，判断哪一侧是边际定价者。

**输出要求**：指出背离、给出两侧证据、提出一个**可证伪的**追问。不要下没有验证路径的结论。

## 五、约束清单

1. **不预测点位**。宏观监测不做点位预测，也不做择时建议（Spec §46）。
2. **不解释单一数据点**。单指标小幅波动不构成信号。
3. **频率不混算**。月频指标不得报「今日变化」。
4. **数据缺失要明说**。指标不可用时标注 `MISSING` / `NO_FIELD`，**不得用近似值填充，不得 forward-fill 造假**（Spec §12）。
5. **区分观测期与发布期**。`2026-08` 的 CPI 在 9 月发布，表述为「8 月 CPI」而非「当前 CPI」。
6. **权重标注 draft**。六维权重未经回测，输出时不得表述为精确度量。

---

## 六、Daily Brief 输出范式

```text
【宏观速览】2026-09-10

一、今日变化
（只写真正变了的，没变的不写。日频看 d1/d5，月频看是否有新发布）

二、主要驱动
（归因到具体指标，不写「受多种因素影响」）

三、跨资产验证
（债 / 汇 / 股 / 商品 是否同向确认）

四、潜在矛盾
（有背离就写，没有就写「未见明显背离」）

五、明日/本周关注
（下一个发布窗口的数据、已触发 RESEARCH_CANDIDATE 的指标）
```

**长度**：300~600 中文字。超过就是没做取舍。
