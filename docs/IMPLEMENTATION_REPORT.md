## 3. 关键设计决策（4 处，需要你知情）

### 3.1 工作台是「一个自包含 HTML」，不是两套前端

`public/macro-workbench.html` 里 ECharts 与数据全部内联（约 2.1 MB），可以离线双击打开、
也可以直接发给别人。React 路由 `app/monitor/macro/page.tsx` 嵌入的是**同一份文件**。

理由：如果 React 再写一套同功能面板，就是两份需要同步维护的可视化代码，必然漂移。
代价是站点入口用了 iframe——对内部工作台这是可接受的取舍。

### 3.2 采集层与评分层严格分离

`macro-collect.mjs` 只负责取数落盘，一行统计都不算；`macro-snapshot.mjs` 只负责算，不碰网络。
这条边界是 Spec §37「AI 不计算 zscore / percentile / change」在工程上的对应物——
**统计量由代码算出并落进快照，LLM 只解释已算好的 signal**。

### 3.3 三种采集模式，而不是每天全量拉

| 模式 | 触发 | 覆盖 |
|---|---|---|
| `daily` | 工作日 16:40 | 日频 33 项（利率/汇率/商品/指数） |
| `release` | 工作日 09:40 | 月频/季频 36 项，只在发布窗口推进 |
| `full` | 手动 | 全部 69 项（6 年窗口，约 30 秒） |

增量模式带**合并语义**：只拉一层时，另一层沿用上轮结果，不会整体覆盖丢历史（已实测验证）。
这是 Spec §27「官方宏观不要每日无脑全量拉取」的落地方式。

### 3.4 单位与维度名中文化

后端存 `cny_per_kg` / `sqm_10k` 这类机器可读单位，前端映射为 `元/公斤` / `万㎡`；
异常表的维度列也从 `growth` 映射为 `增长`。保持数据契约稳定，不把展示需求渗进存储层。

## 4. 实施期修正的真实缺陷（7 处 + 第三轮 3 处，见 §6.5）

这七条都是**跑起来才暴露的**，静态审查发现不了：

### 4.1 HQ 价格序列的 `0` 是缺数据哨兵，不是价格

`ZC00.CZC`（动力煤主力）返回 1,455 行，其中 1,062 行 `close=0`。原实现把 0 当有效值，
导致这个**实际在 2022-12-30 就停更**的序列被判为 `FRESH`，还进入了评分。

修正：HQ 价格类的 0 一律按 `null` 处理，并记录 `zeroSentinelDays` 供追溯。
修正后该指标正确判定为 `DISCONTINUED`（滞后 1,350 天），排除出评分。

### 4.2 注册表用了未登记的方向标签，M2/社融被静默排除

注册表给 `CN_M2` / `CN_TSF` / `CN_TSF_FLOW` / `CN_TSF_GOV` 标的是 `higher_is_looser`，
但 `signal_rules.yaml` 的 `direction_semantics` 只定义了 5 个标签，没有这个。
代码的 fallback 是「未登记 → 降级为 contextual → 不参与打分」，**于是货币信用总量整条线被排除在流动性维度之外，而没有任何报错**。

修正：补齐 7 个方向标签的 `polarity` 定义，并让代码优先从 YAML 读取（配置为唯一真源），
同时新增 `unknownDirections` 上报——今后再出现未登记标签会显式告警而不是静默降级。
修正后流动性维度成员从 5/7 恢复到 7/7，得分从 61.3 修正为 48.8。

### 4.3 热力图有大量空洞

原实现用全局横轴索引，导致每个维度只占用横轴的自己那一段，整张图大片空白。
改为**维度内局部索引**后每行从左侧填满；再叠加人工简称映射
（否则单元格会退化成「当月同比」「累计值」这类无信息量的后缀）。

### 4.4 派生指标被误纳入采集清单

期限利差这类派生指标没有独立数据源，其序列由支撑序列相减得到。
原实现把它们也放进了采集循环，产出 3 条 `EMPTY` 记录污染统计。
修正：采集层只处理有 `ifind.field_code` 的原始指标。

### 4.5 交易所后缀：手册写错了郑商所，且完全没提广期所

手册写郑商所后缀为 `.ZCE`，实测 `FG00.ZCE` 全部返回 `-4210`，正确后缀是 **`.CZC`**。
广期所手册根本没有记载，逐一试错后确定是 **`.GFE`**（`GFEX` / `GF` / `GZ` / `GFA` 全部 `-4210`）。
这两处勘误已写进 `futures_chains.yaml` 的 `exchange_notes`，避免下次重新踩。

### 4.6 主力连续合约卡在僵尸合约上

`XX00.交易所` 是主力**连续**代码，但部分郑商所品种并不跟随主力切换。
实测 `SH00.CZC`（烧碱）指向一个持仓量只剩个位数的失效合约，序列几乎全是 0。
第一版修复用「有效点数」比较，判定 535 > 16 所以不切换 —— 逻辑本身就是错的。

修正：改为按**最新有效日期**比较（`detectedLast > primaryLast` 才切换），
并把解析结果连同 `overlapDays` 一起写入 `work/macro/futures-main.json` 做缓存，
再用 `oiDecaying()` 检测持仓量快速衰减（主力切换前兆）来强制重新探测。

### 4.7 换月价差被算成「行情」（本模块最严重的一处）

`XX00` 主力连续**不复权**。甲醇在 09-08 收 3465、09-10 收 3872，看着是 +11.75% 的大涨，
实际是 09 月合约换到 01 月合约的**价差跳空**，当日真实涨幅只有 1.5%。

修正分两步：
1. 期货层改用 `ensureFuturesSeries(..., { alwaysResolve: true })`，
   解析**真实主力月份合约**（如 `SH701.CZC`、`I2701.DCE`）而非连续代码；
2. 新旧合约切换时用 `rollAdjust()`，以重叠段中位数比值**等比复权**拼接历史序列。

修正后甲醇 5 日 +7.1%、原油 +12.8% 等都是真实涨幅，全品种单日涨跌幅极值逐一复核无残留跳空。
注意：**宏观层的 9 个品种（螺纹/热卷/铜/铝/铁矿/焦煤/动力煤/玻璃/原油）仍沿用 `RB00` 连续**，
以保持六维评分口径不变 —— 两层刻意分开，期货层不参与评分，避免同一变量在宏观与产业链两侧双重计数。

## 5. 期货全品种层与每日汇报

### 5.1 为什么要有第二层

宏观层的 69 项指标回答「经济方向」，但回答不了「具体看哪个品种」。
你提的需求是「想看煤炭就有焦煤，想看化工就有各项化工品」——这需要**全品种产业链视图**。

做法：新增配置文件 `references/futures_chains.yaml`，把候选品种按 7 条产业链分层：

| 产业链 | 品种数 | 分层 |
|---|---|---|
| 黑色·煤焦钢 | 9 | 上游原料（铁矿/焦煤/焦炭/动力煤）→ 中游合金 → 下游钢材 |
| 有色金属 | 8 | 氧化铝 → 基本金属（铜铝锌铅镍锡 + 国际铜） |
| 能源 | 5 | 上游原油 → 下游油品（燃油/低硫燃油/沥青/液化石油气） |
| 化工 | 18 | 上游原料（PX/甲醇/乙二醇/纯碱/烧碱/苯乙烯/橡胶）→ 下游成品（PTA/短纤/瓶片/PP/塑料/PVC/玻璃/尿素） |
| 贵金属 | 2 | 金、银 |
| 农产品 | 12 | 上游原料 → 下游成品（含生猪、油脂油料） |
| 新能源·航运 | 7 | 新能源金属（碳酸锂/多晶硅/工业硅）+ 航运（集运欧线） |

**61 个候选品种全部经 `macro-probe-futures.mjs` 实测**，60 个可用（仅动力煤已停更）。
所有 field_code 都来自实测，无一处猜测。

### 5.2 两层严格分离

| | 宏观层 | 期货层 |
|---|---|---|
| 指标来源 | `indicator_registry.yaml` | `futures_chains.yaml` |
| 合约口径 | `RB00` 等主力连续 | 真实主力月份合约 + 换月复权 |
| 是否参与六维评分 | 是 | **否** |
| 用途 | 宏观方向、异常、背离 | 产业链强弱、价差、传导信号 |

同一个 `field_code` 只请求一次，采集层按 `M|code` / `F|code` 分组后再分发，避免重复调用。

### 5.3 每日汇报

`scripts/macro-report.mjs` 把快照编排成 **12 个章节**的固定结构汇报，输出
`public/macro-daily-report.md`（全文）+ `work/macro/report.json`（工作台面板用区块）。

章节：摘要 → 宏观六维状态 → 指标极值 → 跨资产背离 → 重点异常 →
期货产业链总览 → 期货领涨领跌 → **产业链深读**（7 条链逐条展开，煤炭与化工的每个品种都在里面）
→ 主力价差 → 链内传导信号 → 观察清单 → 数据质量与口径。

关键约束（沿用 Spec §37）：

- **零重算**：筛选、排序、四舍五入、措辞拼装全部由代码完成，出现的每个数字都直接来自 snapshot；
- **阈值集中**：所有判定阈值（`|z|≥2`、分位 5%/95%、持仓量 ±30% 等）写在文件顶部 `THRESH` 常量里，便于审计；
- **不调用 LLM**：汇报是「事实层」。模型的职责是在其上写 `今日变化 → 驱动 → 验证 → 矛盾 → 关注` 的解释，不得改写数字；
- **日间对比**：若 `work/macro/snapshots/` 里有更早的快照，摘要会自动带上综合分与各维度的较上一交易日变化。

工作台首屏即为汇报卡片，默认折叠（先给摘要），可一键展开全文、复制 Markdown、下载 `.md`。

### 5.4 可视化与宏观市场层（第二轮补齐）

第一版工作台的问题是「表多图少」——能查数但看不出**过去怎么走的**；汇报也只有期货产业链，
利率、股指、汇率这些最常被追问的宏观项没有位置。第二轮针对性补齐：

**汇报从 12 章扩到 20 章**，新增宏观市场层 8 章（利率与资金面 / 权益与汇率 / 货币与信用 /
增长与景气 / 通胀 / 地产 / 消费与外需 / 全指标总表）。每章是一张逐指标表：最新值、
1/5/20 期变化、近一年 Unicode 迷你走势、1 年分位、z 与方向校正后 z。

**变化单位按指标性质分流**，这是本轮修掉的一个真实缺陷：第一版把收益率上行
1.9bp 显示成「+0.0019」，可读性为零。现规则：

| 指标性质 | 单位 | 例 |
|---|---|---|
| 收益率、资金利率 | bp | 10Y `-2.4bp` |
| 其他百分比类（CPI/PPI/M2） | pp | CPI `+0.30pp` |
| 股指 | % | 沪深300 `-2.48%` |
| 其他指数（PMI/BDI/景气） | 点 | PMI `+0.6点` |
| 价格、金额 | % | 铜 `+0.55%` |

**工作台新增三个可视化能力**：

| 面板 | 内容 |
|---|---|
| 宏观市场走势 | 4 张折线：资金利率、权益指数（归一化）、人民币汇率、大宗与高频商品（归一化）；区间 3M/6M/1Y/2Y 可切 |
| 宏观基本面走势 | 6 张月频折线：通胀、货币与信用、景气调查、地产、消费与外需、工业与利润；PMI 图带 50 荣枯线 |
| 宏观指标总表 | 72 项指标，按板块/维度筛选、4 种排序、行内嵌 SVG 迷你走势 |

异动榜与期货涨跌榜也加了行内迷你走势。迷你走势一律只取**近一年**（日频 250 点），
与「1 年分位」口径对齐；着色只表示首尾方向。日频序列的嵌入上限从 320 点提到 500 点，
让「近 2 年」区间有足够数据。

**踩到的坑**：图表图例原来直接截取指标名最后一个冒号后的片段，而注册表里大量指标名以
「当月同比 / 累计同比」结尾 —— 通胀图 4 条线全叫「当月同比」。改为按 id 硬编码 `LABELS` 短名。

**新增的共享数据块**（避免前端重算，Spec §37）：`snapshot.indicators[]`（全 72 项指标的
latest / changes / pctChg / z / 分位 / category / layer）与 `snapshot.categories{}`（11 组分组索引），
报告与工作台读同一份数。

**缺陷 B：ECharts 在 0×0 容器里初始化后不会自己重画**（iframe / 折叠 / 窄屏场景）。

## 6.6 第四轮（用户反馈：预览面板仍空白 / 日报要给「当日显著偏离」结论）

### 6.6.1 预览面板空白 → 顺着"容器尺寸正常但 canvas 空白"查到底

第三轮加了自检，但自检只看了**容器**的 `getBoundingClientRect()`——容器有宽高、
canvas 却是 0×0 或 1×1 时判不出来，于是"面板没图"依旧静默通过。根因仍是
**ECharts 在 `display:none` / iframe 首帧 / 折叠面板里初始化会画出 0×0 canvas，
容器撑开后它不会自动重画**。

这一轮把防御做成了三层，而不是再打一个补丁：

1. **自检改为查 canvas 像素**：`chartDiag()` 读 `canvas.width/height`，按 `devicePixelRatio`
   折算后与容器比对，`< 0.9×` 即判定为废图（此前的判据根本抓不到这个 case）。
2. **每个面板登记重画入口**：新增 `RENDERERS[nodeId]` 表，`drawLine()` / `mk()` 均登记，
   `window.__macroRedraw__()` 可一键重画全部面板；`mk()` 重画前先 `dispose` 旧实例，
   避免重复 init 泄漏。两个绘制函数都包了 `try/catch`，**单图失败不再中断整页**。
3. **四重触发兜底**：`ResizeObserver` + `IntersectionObserver` + `visibilitychange`
   + `[400, 900, 1800, 3200]` 多时间点 `resize()`。
   顶部徽标 `chartChip` 常显自检结果，右下角诊断面板可展开完整 UA / 错误 / 各面板 canvas 尺寸。

**实测（Edge 无头，`scripts/macro-diag-render.mjs`）**：

| 场景 | 结果 |
|---|---|
| `normal` | 20/20 有 canvas · 0 个 JS 错误 · 徽标"全部 20 张正常" |
| `hidden`（先 `display:none` 1.5s 再显示，复现预览/折叠） | 20/20 有 canvas · 0 个 JS 错误 |

顺带揪出并修掉：`futHeatChart`（品种热力图）漏登记 `CHARTS`/`RENDERERS`，
canvas 被裁成 100px 宽——这个面板此前一直画不全。

### 6.6.2 日报新增「今日显著偏离」（用户的核心诉求）

诉求原文：「当日出现了明显偏离度的涨幅或者跌幅的时候，这个需要单独地标出来。
在日报里面就是给它加注嘛，这样可以了解到当天有什么出现了及时性的变化。」

落地方式（严格守住 Spec §37：**只判定，不重算**）：

- **新增指标 `chg1Extreme`**（在采集/快照层算好）：本期 `|1 期变化|` 落在
  **该指标自身近 3 年全部单期 `|变化|` 分布**中的分位。
  为什么不能用现成的 `z1y`：`z1y` 说明的是"现在位置高不高"，回答不了"今天这一下变化大不大"。
  一个指标可以位置很中性、今天却跳一记大变化，`chg1Extreme` 才抓得住。
- **日报第 2 章「今日显著偏离」**（紧随摘要，摆在最前面）：
  先给**结论句**（共几项、涨/跌各几项、最极端的是谁、幅度、在自身 3 年里排到第几十分位），
  再分**上涨侧 / 下跌侧**两张榜（各取 6 项），其后**月频 / 季频单独成表**
  （标注"观测期不一定是今天"，避免与当日口径混淆），末尾给**加注口径说明**。
- **固定标注词表**（避免自由发挥）：`刷一年新高` / `刷一年新低` / `变化极端` /
  `变化显著` / `位置极端` / `变化+位置双极端` / `持仓放大`。
- **涨跌按原始方向**标注，不做方向校正——这一章回答的是"涨跌"，不是"好坏"。
- **双层去重**：宏观层有一批"XX主力"期货收盘价指标（沪铜主力 / 原油主力 / 铁矿石主力…），
  与期货层是同一标的。归一化（去掉末尾"主力"后比对）后**只保留期货层**（含持仓量与产业链分组），
  避免同一行情上榜两次。实测榜单从 36 项收敛到 33 项，无重复标的。
- **工作台同步**：日报章节由工作台「每日汇报」面板动态渲染（自动出现），
  并在「今日全景」里直接引用该章结论句——两处同源，不会各说各话。
